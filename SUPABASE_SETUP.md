# Supabase Setup Guide for Shared Gallery

This guide explains how to configure Supabase to enable users from different locations to upload and view each other's plant images.

## Prerequisites

1. A Supabase project (create one at https://supabase.com)
2. Your Supabase project URL and anon/public key

## Step 1: Configure Supabase Credentials

### Current Configuration Method: Inline Configuration

The app now uses **inline configuration** in `index.html` for reliable GitHub Pages deployment. This is the current method being used.

**To update Supabase credentials:**

1. **Edit `index.html`** and find the inline configuration script:
   ```html
   <script>
     window.SUPABASE_CONFIG = {
       url: 'https://your-project.supabase.co',
       key: 'your-anon-key-here'
     };
   </script>
   ```

2. **Replace the placeholder values** with your actual Supabase credentials

3. **Deploy the changes:**
   ```bash
   git add index.html
   git commit -m "Update Supabase credentials"
   git push origin main
   ```

**Advantages of inline configuration:**
- ✅ Works reliably on GitHub Pages
- ✅ No path issues with base URLs
- ✅ Simple to maintain
- ✅ No external file dependencies

### Alternative: Environment Variables (For Local Development)

For local development, you can use environment variables:

1. **Create `.env.local`:**
   ```bash
   cp .env.example .env.local
   ```

2. **Add your credentials:**
   ```bash
   VITE_SUPABASE_URL=https://your-project.supabase.co
   VITE_SUPABASE_PUBLISHABLE_KEY=your-anon-key-here
   ```

3. **Run locally:**
   ```bash
   npm run dev
   ```

**Note:** Environment variables take priority over inline configuration in local development.

## Step 2: Create Supabase Database Table

Run this SQL in your Supabase SQL Editor:

```sql
-- Create scans table if it doesn't exist
create table if not exists public.scans (
  id bigint generated by default as identity primary key,
  image_url text not null,
  image_hash text,
  plant_name text,
  status text,
  confidence integer,
  source text,
  storage_path text,
  created_at timestamp with time zone default timezone('utc'::text, now()) not null
);

-- Add image_hash and storage_path columns if they don't exist
alter table public.scans
  add column if not exists image_hash text,
  add column if not exists storage_path text;

-- Create unique index on image_hash to prevent duplicates
create unique index if not exists scans_image_hash_key
  on public.scans (image_hash)
  where image_hash is not null;

-- Enable Row Level Security (optional, for better security)
alter table public.scans enable row level security;

-- Allow anyone to read scans (for shared gallery)
create policy "Anyone can view scans"
  on public.scans for select
  to anon, authenticated
  using (true);

-- Allow anyone to insert scans (for shared uploads)
create policy "Anyone can insert scans"
  on public.scans for insert
  to anon, authenticated
  with check (true);

-- Allow users to delete their own scans (optional)
create policy "Users can delete own scans"
  on public.scans for delete
  to anon, authenticated
  using (true);
```

## Step 3: Create Supabase Storage Bucket

1. Go to your Supabase project dashboard
2. Navigate to **Storage** → **New bucket**
3. Create a bucket named `plant-images`
4. Make it **Public** (important for image access)

## Step 4: Configure Storage Policies

Run this SQL in your Supabase SQL Editor:

```sql
-- Allow anyone to upload to the plant-images bucket
create policy "Anyone can upload plant images"
  on storage.objects for insert
  to anon, authenticated
  with check (bucket_id = 'plant-images');

-- Allow anyone to view images in the plant-images bucket
create policy "Anyone can view plant images"
  on storage.objects for select
  to anon, authenticated
  using (bucket_id = 'plant-images');

-- Allow anyone to delete images from the plant-images bucket
create policy "Anyone can delete plant images"
  on storage.objects for delete
  to anon, authenticated
  using (bucket_id = 'plant-images');
```

## Step 5: Update GitHub Actions Workflow

Update `.github/workflows/deploy.yml` to include the Supabase environment variables:

```yaml
- name: Build
  run: npm run build
  env:
    VITE_SUPABASE_URL: ${{ secrets.VITE_SUPABASE_URL }}
    VITE_SUPABASE_PUBLISHABLE_KEY: ${{ secrets.VITE_SUPABASE_PUBLISHABLE_KEY }}
```

## How It Works

- **Local Storage**: Falls back to IndexedDB if Supabase isn't configured
- **Shared Storage**: When Supabase is configured, all users see the same gallery
- **Image Deduplication**: Uses SHA-256 hash to prevent duplicate uploads
- **Cross-Platform**: Works on any device with internet access

## Troubleshooting

### Images not appearing for other users
- **Runtime config**: Check that `public/config.js` is properly configured
- **Environment variables**: Check that they are set correctly in production
- Verify the `plant-images` bucket is public
- Ensure storage policies allow read access
- Check browser console for specific error messages

### Upload errors
- Check that the user has permission to upload to the bucket
- Verify the bucket name matches exactly: `plant-images`
- Check Supabase logs for specific error messages
- Ensure runtime config or environment variables are set

### Configuration not working
- **Runtime config**: Check browser console for configuration source
- **Environment variables**: Ensure variables start with `VITE_` prefix for Vite
- Check that GitHub Actions secrets are set correctly (if using env vars)
- Verify the workflow includes the environment variables in the build step
- Look for console warnings about missing configuration

### Debug Console Messages
- `✅ Supabase initialized successfully` - Configuration is working
- `⚠️ Supabase not configured` - Missing credentials
- `🔧 Using runtime configuration` - Using config.js
- `🔧 Using environment variables` - Using build-time env vars
- `📊 Found X images in Supabase` - Database connection working

## Security Notes

- **Never commit** your Supabase service role key to the repository
- **Use only the anon/public key** in frontend code
- **Consider adding Row Level Security** for production use
- **Regular backups** of your Supabase database are recommended
