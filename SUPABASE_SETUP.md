# Supabase Setup Guide

This guide explains how to connect Crop Doctor to Supabase for a shared gallery and collaborative crop-image review workflow.

## Overview

The app supports both local and shared gallery modes:

- Local mode stores scans in the browser for quick demo testing
- Shared mode stores uploads in Supabase so multiple users can view the same crop images
- The app gracefully falls back when Supabase is not configured

## Why This Matters

For presentations and demo use, it is useful to show that the project can work across devices and users. Supabase allows the gallery to behave like a shared crop inspection board that works from mobile, tablet, and desktop screens.

## Prerequisites

1. A Supabase project at https://supabase.com
2. A project URL
3. A public or anon key
4. Access to the SQL editor and Storage section of the dashboard

## Step 1: Add Project Credentials

The app uses inline configuration in index.html to keep deployment simple on GitHub Pages.

Update the block below with your real values:

```html
<script>
  window.SUPABASE_CONFIG = {
    url: 'https://your-project.supabase.co',
    key: 'your-anon-key-here'
  };
</script>
```

Then deploy the update:

```bash
git add index.html
git commit -m "Update Supabase credentials"
git push origin main
```

### Benefits of this setup

- works well with GitHub Pages
- avoids path issues during deployment
- keeps configuration simple for demos
- supports quick cross-device testing

## Step 2: Create the Scans Table

Run this SQL in the Supabase SQL editor:

```sql
create table if not exists public.scans (
  id bigint generated by default as identity primary key,
  image_url text not null,
  image_hash text,
  plant_name text,
  status text,
  confidence integer,
  source text,
  storage_path text,
  created_at timestamp with time zone default timezone('utc'::text, now()) not null
);

alter table public.scans
  add column if not exists image_hash text,
  add column if not exists storage_path text;

create unique index if not exists scans_image_hash_key
  on public.scans (image_hash)
  where image_hash is not null;

alter table public.scans enable row level security;

create policy "Anyone can view scans"
  on public.scans for select
  to anon, authenticated
  using (true);

create policy "Anyone can insert scans"
  on public.scans for insert
  to anon, authenticated
  with check (true);

create policy "Users can delete own scans"
  on public.scans for delete
  to anon, authenticated
  using (true);
```

## Step 3: Create the Storage Bucket

1. Open your Supabase dashboard
2. Go to Storage
3. Create a bucket named plant-images
4. Keep the bucket public so uploaded images can be viewed in the gallery

## Step 4: Configure Storage Policies

```sql
create policy "Anyone can upload plant images"
  on storage.objects for insert
  to anon, authenticated
  with check (bucket_id = 'plant-images');

create policy "Anyone can view plant images"
  on storage.objects for select
  to anon, authenticated
  using (bucket_id = 'plant-images');

create policy "Anyone can delete plant images"
  on storage.objects for delete
  to anon, authenticated
  using (bucket_id = 'plant-images');
```

## Step 5: Add GitHub Actions Variables

If you use the deployment workflow, include the Supabase values in the build step:

```yaml
- name: Build
  run: npm run build
  env:
    VITE_SUPABASE_URL: ${{ secrets.VITE_SUPABASE_URL }}
    VITE_SUPABASE_PUBLISHABLE_KEY: ${{ secrets.VITE_SUPABASE_PUBLISHABLE_KEY }}
```

## Step 6: Validate the Setup

1. Run the app locally:

```bash
npm run dev
```

2. Upload an image and check whether it appears in the shared gallery.
3. Open the deployed site and confirm the app still works on mobile, tablet, and desktop.
4. Check the browser console for the Supabase status or connection messages.

## How the System Works

- Local mode: stores scans in the browser without external setup
- Shared mode: allows all connected users to see the same gallery data
- Deduplication: avoids repeated uploads through image hash comparison
- Cross-platform support: works across phone, tablet, and laptop screens

## Troubleshooting

### Images are not appearing

- check whether the Supabase URL is valid
- verify the public key is correct
- confirm the bucket name is exactly plant-images
- ensure the SQL policies are enabled

### Uploads fail

- make sure the bucket is public
- confirm permissions are correct
- check the browser console for the exact error message

### Deployment issues

- confirm the app is reading the runtime configuration correctly
- verify environment variables use the VITE_ prefix
- ensure the GitHub workflow includes the required secrets

## Security Notes

- never commit a service role key to a public repository
- use the anon or public key only for browser-facing access
- review storage rules before moving into production
- keep backups of important scan records

## Final Note

This setup allows Crop Doctor to support a shared gallery and a presentation-ready cross-device demo experience for crop image review, scanning, and collaboration.
